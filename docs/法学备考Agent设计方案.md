# 法学备考 Agent 产品设计方案

> 面向法学生的智能备考助手 · RAG + 用户画像 + Agent 编排

---

## 一、项目背景与目标

### 1.1 背景

法考（法律职业资格考试）被誉为"天下第一考"，涵盖 8 大科目、数百部法律法规、上万条法条。传统备考方式存在以下痛点：

- **法条检索效率低**：翻书/搜索找法条耗时，且难以快速定位关联条文
- **知识体系零散**：各科目知识点交叉关联，学生难以建立完整知识图谱
- **练习反馈滞后**：做题后只能对答案，缺乏针对性讲解和举一反三
- **学习进度难量化**：不清楚自己哪些知识点掌握了、哪些是薄弱项

### 1.2 目标

打造一款**面向法学生的智能备考 Agent**，核心能力：

1. **响应快速**：常见问题秒级响应，复杂问题 < 3 秒出首字
2. **数据准确**：法条引用精确到条文编号，答案有据可查
3. **引用明确**：每个结论标注来源，可点击查看原文
4. **个性化学习**：记录用户画像，动态了解学习情况，自适应推荐

## 三、核心模块设计

### 3.1 法条知识库（准确性的基石）

#### 数据来源

| 数据源 | 说明 | 获取方式 |
|---|---|---|
| 国家法律法规数据库 | 最权威的官方法条 | 官网公开 / 开源镜像 |
| 司法解释 | 最高法、最高检解释 | 官网公开 |
| 法考官方教材（四大本） | 备考针对性强 | 公开资料 |
| 历年法考真题 + 解析 | 练习必备 | 公开渠道整理 |
| 中国裁判文书网 | 判例参考 | 公开数据 |

#### 法条结构化方案

每条法条按以下结构存储，确保引用精确：

```yaml
law_article:
  id: "art_20240101_00311"
  law_name: "中华人民共和国民法典"
  law_code: "CivilCode"
  book: "物权编"
  chapter: "第九章 所有权取得的特别规定"
  article_no: "第三百一十一条"
  article_title: "善意取得"
  content: |
    无处分权人将不动产或者动产转让给受让人的，所有权人有权追回；
    除法律另有规定外，符合下列情形的，受让人取得该不动产或者动产的所有权：
    （一）受让人受让该不动产或者动产时是善意；
    （二）以合理的价格转让；
    （三）转让的不动产或者动产依照法律规定应当登记的已经登记，
         不需要登记的已经交付给受让人。
  tags: ["物权", "善意取得", "所有权"]
  related_articles:
    - "第三百一十二条"  # 遗失物善意取得
    - "第三百一十三条"  # 善意取得的法律效果
  effective_date: "2021-01-01"
```

#### 分块策略

> ⚠️ 法条必须按**条文粒度**分块，不能按段落随意切分，否则引用不准。

- **基础分块**：单条法条为一个 chunk
- **扩展分块**：同一章节内连续法条组成大 chunk（用于上下文理解）
- **元数据**：每条 chunk 必须携带完整法律名称、条文号、章节路径

### 3.2 RAG 检索系统（快 + 准）

#### 分层检索架构

```
用户查询
   │
   ▼
┌─────────────────────────────────┐
│     L1: 关键词检索（BM25）      │  ← 毫秒级响应，法条编号精确匹配
│  + 法条编号倒排索引             │
└───────────────┬─────────────────┘
                │ 并行
┌───────────────▼─────────────────┐
│     L2: 向量检索（语义）        │  ← 语义相似度，概念类问题
│  bge-small-zh / 智谱 Embedding  │
└───────────────┬─────────────────┘
                │
                ▼
┌─────────────────────────────────┐
│     L3: 重排序（Rerank）        │  ← 提升 Top-K 准确率
│  bge-reranker-base             │
└───────────────┬─────────────────┘
                │
                ▼
         返回上下文给 LLM
```

#### 加速手段

| 手段 | 效果 | 适用场景 |
|---|---|---|
| 热门法条 Redis 缓存 | 首字延迟 < 200ms | 高频概念如"善意取得""诉讼时效" |
| BM25 先粗筛 + 向量精排 | 检索时间 < 500ms | 大多数查询 |
| 小模型 Embedding | 向量化速度提升 5x | 全量检索 |
| 流式输出 | 首字延迟 < 1s | 所有生成类回答 |

### 3.3 引用溯源机制（可信度核心）

#### 引用模板

答案生成时强制带引用，格式如下：

```
善意取得，是指无处分权人将其动产或不动产转让给受让人，
如果受让人取得该财产时出于善意，则受让人将依法取得对
该财产的所有权或其他物权的制度[1]。

其构成要件包括：
1. 受让人受让该不动产或者动产时是善意的[1]
2. 以合理的价格转让[1]
3. 转让的不动产或者动产依照法律规定应当登记的已经登记，
   不需要登记的已经交付给受让人[1]

---
📚 引用来源：
[1] 《中华人民共和国民法典》第三百一十一条 【善意取得】
    无处分权人将不动产或者动产转让给受让人的，所有权人有权追回；
    除法律另有规定外，符合下列情形的，受让人取得该不动产或者动产的所有权：
    （一）受让人受让该不动产或者动产时是善意；
    （二）以合理的价格转让；
    （三）转让的不动产或者动产依照法律规定应当登记的已经登记，
         不需要登记的已经交付给受让人。
    → 点击查看完整法条
```

#### 引用校验机制（防幻觉）

1. **生成阶段**：Prompt 强制要求每个论点标注引用来源编号
2. **校验阶段**：后处理检查——答案中引用的法条编号是否真实存在于检索到的上下文中
3. **兜底策略**：如发现编造法条，自动标记并替换为"未找到对应法条，建议核实"

#### 掌握度计算算法

**贝叶斯更新思路**：

```
初始掌握度 = 0.3（新手基线）

每次答题后更新：
- 答对：mastery = mastery + (1 - mastery) × α
  - α 与题目难度正相关（难题答对提升更多）
- 答错：mastery = mastery × β
  - β 与题目难度负相关（简单题答错下降更多）

知识点关联传播：
- 答对"善意取得" → 相关的"物权变动""公示公信原则"掌握度小幅上升
- 答错"合同解除" → 相关的"违约责任""合同履行"掌握度小幅下降
```

#### 画像的应用场景

| 场景 | 画像作用 |
|---|---|
| 智能出题 | 根据薄弱点 + 遗忘曲线推荐题目 |
| 难度自适应 | 正确率高 → 升难度；正确率低 → 降难度 |

| 复习提醒 | 基于艾宾浩斯遗忘曲线，到期自动提醒复习 |

## 五、性能优化方案

### 5.1 响应速度优化

1. **流式输出（SSE）**：答案边生成边返回，首字延迟 < 1s
2. **检索并行化**：BM25 和向量检索同时发起，取并集后 rerank
3. **热点缓存**：
   - 高频问题结果缓存（Redis TTL 24h）
   - 热门法条全文缓存（内存）
4. **预加载机制**：用户进入某科目时，预加载该科高频法条
5. **模型分级路由**：简单问题用小模型，复杂问题用大模型

### 5.2 准确性优化

1. **分层检索 + 重排序**：召回率 + 精确率兼顾
2. **引用校验**：生成后校验法条真实性，防幻觉
3. **Prompt 约束**：严格要求基于上下文回答，不编造
4. **多轮澄清**：对模糊问题先追问确认再回答
5. **置信度评估**：低置信度答案标注"仅供参考，请核实法条原文"

## 八、核心设计原则

1. **法条准确性优先**：宁可少答，不可错答。不确定时明确告知需核实
2. **引用必溯源**：每个法条结论必须标注出处，可点击查看原文
3. **不替代真题训练**：AI 是辅助工具，提醒用户以真题为主
4. **用户隐私保护**：学习数据加密存储，用户可导出/删除
5. **渐进式复杂度**：先做好基础问答，再逐步加高级功能
6. **移动端优先**：法学生多用碎片时间学习，移动端体验很重要

## 九、风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| AI 幻觉编造法条 | 严重，误导学习 | 引用校验机制 + 低置信度标注 + 提示核实原文 |
| 法条更新不及时 | 中等，答案过时 | 定期同步官方法条库 + 标注生效时间 |
| 响应速度慢 | 影响体验 | 分层检索 + 缓存 + 流式输出 + 模型分级 |
| 数据版权问题 | 法律风险 | 仅用公开免费数据 + 明确声明仅供学习 |
| 用户留存低 | 产品价值不足 | 学习报告 + 打卡机制 + 个性化推荐 |
