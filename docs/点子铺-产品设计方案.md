# 点子铺（暂名）· 产品设计方案

> 一个能自己长大的 AI 应用：朋友通过对话为它设计功能，好点子直接实现在它身上，持续"长"出新功能。

## 1. 定位与核心理念

**一句话定位**：免注册、聊着聊着就把**本应用的下一个功能**设计出来的「自我生长产品」。

**解决的问题**：朋友有好点子但说不清楚、说过就忘；你收到的需求是一堆零散的微信语音。中间缺一个「AI 访谈官」——把闲聊变成结构化的功能设计；且好点子不外流，直接实现在这个应用身上，让它不断长出新功能。

**核心理念**：
1. **只谈"做什么"，不谈"怎么做"**——创意阶段聊技术是最大的效率杀手
2. **对话即设计**——朋友不需要懂产品文档，说人话即可，AI 负责翻译成功能卡
3. **创意长在应用上**——被采纳的点子直接实现在本应用，朋友打开就能用上"自己设计的功能"

**核心循环**：你发起创意主题 → 邀请朋友 → 朋友与主理人对话设计功能 → 功能卡沉淀 → 你审阅采纳 → 在本应用实现上线 → 朋友用上新功能、收到署名感谢 → 带来更多灵感。应用由此自我生长。

## 2. 用户角色

| 角色 | 是谁 | 做什么 |
|------|------|--------|
| **发起人**（你） | 平台的主人 | 创建创意主题、发邀请、审阅功能卡、定优先级、实现、发回执 |
| **创意合伙人**（朋友） | 被邀请的人 | 免注册进入对话，与 AI 访谈官聊天，设计功能，确认功能卡 |
| **主理人**（AI） | 访谈官角色 | 主持对话、追问场景、提炼功能卡、拒绝聊技术 |

## 3. 核心体验流程

```
① 你创建主题  →  ② 生成邀请链接  →  ③ 朋友免注册进入（起个昵称）
→  ④ 与主理人流式对话  →  ⑤ 对话中实时蹦出"功能卡"，朋友点确认
→  ⑥ 卡片进入看板  →  ⑦ 你审阅/标记状态  →  ⑧ 你在本应用实现上线  →  ⑨ 朋友用上 + 感谢卡
```

**① 创建主题**：一次聚焦一个方向（如"AI 帮我带娃的点子"），主题页有一句给朋友的召唤语。
**③ 免注册进入**：链接带一次性 token，朋友起个昵称就能开聊，全程不需要账号。
**④⑤ 访谈对话**：主理人流式回复（逐字输出，体验好）；每当聊透一个功能，主理人就把一张功能卡以气泡形式摆出来，朋友可以「确认 / 让我再改改 / 不要这个」。
**⑥⑦ 看板**：你登录后看到所有功能卡瀑布流，可按主题、来源朋友、状态、创意值筛选。
**⑧⑨ 实现与回执**：采纳的功能直接实现在本应用并上线；卡片标记"已实现"时自动生成"感谢卡"（功能名 + 你的一句话感谢 + 去试试入口），朋友下次进入时看到——自己的点子已经长在这个应用里了。

## 4. 主理人（AI 访谈官）设计 —— 本产品的灵魂

### 4.1 人设
一位好奇心旺盛的产品合伙人：热情、会说人话、从不泼冷水、擅长把模糊的"要是有个啥就好了"变成具体的功能描述。称呼朋友为"合伙人"。

**随身带功能清单**：主理人始终知道本应用已有哪些功能。朋友提议已有功能时，委婉告知并引导升级玩法（"这个已经能做啦，如果给它加一个超能力，你会加什么？"）；避免重复点子，也把对话引向"让现有功能变得更好"。

### 4.2 访谈节奏（四段式）

| 阶段 | 目标 | 主理人话术风格 |
|------|------|----------------|
| **破冰** | 打开话题 | "最近有没有哪个瞬间，让你冒出过'要是有个XX就好了'的念头？" |
| **发散** | 拓展细节 | 借力提问："如果它像你身边的某个人一样贴心，你希望像谁？为什么？" |
| **收敛** | 固化功能 | "我把刚才的想法整理成一张功能卡，你看这样理解对吗？" |
| **确认** | 沉淀入库 | 卡片气泡展示，等朋友点头；确认后继续追问下一个灵感 |

一次对话可产出多张卡。对话结束时主理人生成「本次访谈小结」：聊出了什么、确认了哪几张卡、还留了什么悬念。

### 4.3 三不原则（硬约束）

- **不谈技术**：朋友问"这个用大模型能实现吗？"→ "技术交给我操心，你只管许愿～ 你希望它做到什么程度？"
- **不写代码、不聊架构**：出现"数据库""接口""模型微调"等词时，温和转译回功能语言
- **不泼冷水**：不说"这个做不到"，只说"如果先做一小步，你最想要哪一小步？"

### 4.4 场景追问模板

每个功能必须聊透四件事（缺一不可，主理人会追问）：
1. **谁在用**：这个功能是给谁的？就你自己，还是也想给某某用？
2. **什么时机**：什么情况下会想用它？（起床后？无聊时？烦躁时？）
3. **要什么反应**：你希望它给你什么感觉的东西？（文字？图？一段歌？一句话戳心窝？）
4. **没有它时**：如果它没反应/说错了，你能接受怎样？

### 4.5 功能卡提炼规则

主理人在对话中每确认一个功能，输出结构化卡片（机器可读）：

| 字段 | 说明 | 示例 |
|------|------|------|
| 标题 | 动宾短语 | "每天早上给我一句专属好运签" |
| 一句话说明 | 说人话的功能描述 | 醒来后根据今天日程给一句打气的话 |
| 谁在用 | 用户角色 | 加班多的上班族 |
| 什么时机 | 触发场景 | 早上闹钟响后第一次打开 |
| 要什么反应 | 输出的样子 | 一句话 + 一个今日幸运色 |
| 边界情况 | 没得用时怎么办 | 看到一句话解释 + 昨天的存档 |
| 创意值 | 主理人评 1~5 星（新颖度） | ★★★★ |
| 来源 | 哪位合伙人、哪场对话 | 昵称 + 日期 |

**卡片里刻意没有技术字段**（用什么模型、什么框架）——这是"只谈创意"原则在数据结构上的体现。

## 5. 功能卡状态机

```
新芽（AI 刚提炼，朋友待确认）
  → 已确认（朋友点头）
      → 已采纳（你决定做）→ 已实现（已在本应用上线，触发感谢卡）
      → 已谢绝（温和拒绝，可选填一句理由，朋友可见"下次一定"）
```

## 7. 现有工程复用（简表）

| 已有 | 变成 | 改动量 |
|------|------|--------|
| 手机号登录 + JWT | 发起人登录 | 基本不动；新增访客 token（邀请链接用） |
| SSE 流式对话（后端+前端） | 主理人访谈对话 | 换 system prompt；新增卡片事件消息类型 |
| GLM 模型配置 | 主理人大脑 | 不动 |
| React 聊天页 | 访谈页 | 换皮 + 功能卡气泡组件 |
| PG 数据库 | 卡片/主题/会话存储 | 新增 3 张表；users 不动 |
| GitHub Actions 自动部署 | 全套部署 | 不动 |

> MVP 阶段复用率约 70%，新增核心只有三块：邀请免注册、功能卡数据链路、看板页面。

## 8. 关键体验原则

1. **朋友零门槛**：不注册、不学概念，全程像聊天，卡片确认用大白话（"这样理解对吗？"）
2. **卡片的仪式感**：确认一张卡时有小动效（发光/盖章），让"我的想法被记录了"有实感
3. **你的一眼价值**：看板默认按"创意值 + 点赞"排序，先看到最亮的点子
4. **回执必到**：任何被实现的卡，朋友一定能在应用里用上、并看到署名感谢——这是让创意持续来的燃料

## 9. 风险与边界

| 风险 | 对策 |
|------|------|
| 朋友把话题带偏到技术 | 三不原则硬约束 + 卡片无技术字段，物理上没地方聊技术 |
| 灌水/重复点子 | V1 相似卡合并 + 点赞自然淘汰 + 单场对话卡片数上限（建议 5） |
| 冷启动没人聊 | 你先自导 3 场"示范访谈"沉淀种子卡；邀请文案给足面子（"就差你的点子了"） |
| 隐私顾虑 | 邀请进入页明示：对话仅你和主理人可见，卡片仅项目内可见 |
| 创意归属纠纷 | 卡片永久署名（合伙人昵称），导出物保留署名字段 |
| 点子太多实现不过来 | 采纳率对朋友透明；「已谢绝」必须附一句温度理由；看板标"排队中"管理预期 |
