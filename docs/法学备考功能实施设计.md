## 二、总体架构：原方案 → 现有栈映射

| 原方案选型 | 内嵌实现 | 说明 |
|---|---|---|
| FastAPI (Python) | Spring Boot `law` 包 | 现有单体，一门语言 |
| Vue 3 | React 18 现有 web/ | 复用气泡/SSE/移动端适配 |
| Milvus | PostgreSQL + pgvector | 几千条法条量级，pgvector 足够 |
| Elasticsearch (BM25) | 代码级法条编号解析 + pg_trgm | 编号正则精确查；关键词 trgm 相似度 |
| bge-reranker 本地 | glm-4-flash 对 top10 轻量打分（W4 接入，可省略） | 免本地模型运维 |
| Redis | Caffeine 进程内缓存 | 单机场景 |
| Celery | @Async + CompletableFuture | 现有异步模式 |
| LangGraph | AgentRunner 内核 + 意图路由 | 已有结构化 agent 内核（剥围栏+重试内置） |
| bge-small-zh 本地 Embedding | 智谱 embedding-3 API（1024 维） | HTTP 直调，30 行客户端 |
| GLM-4.5-Air 等 4 档 | **glm-4.7**（生成/批改/报告）+ **glm-4-flash**（分类/出题候选） | 实际可用仅此两档 |

新增外部依赖仅两项：**pgvector 扩展**（PG 镜像换 `pgvector/pgvector:pg16`）+ **hibernate-vector**（jar 内依赖，vector 字段映射）。部署链路（GitHub Actions → jar → systemd）零变更。

## 三、会话与模式设计（核心修正）

### 3.1 mode 换挡机制

- `idea_sessions` 新增一列 `mode VARCHAR(16) DEFAULT 'host'`（`host` 本色 / `law` 法学）
- 前端「法」tab 切换 = 请求带 mode 上行，后端同步落会话字段；**同一场会话换挡，历史不分裂**
- 混合历史：一场对话可自然交织闲聊与法学问答，仙官记忆跨模式连续（法学模式记得你聊过的备考计划，本色模式知道你问过哪些法条）

### 3.2 IdeaChatService 内挂法学分支

mode=law 时走独立分支：

| 环节 | host 模式（现有） | law 模式（新增） |
|---|---|---|
| system prompt | 百晓仙君 HOST_PROMPT | 法学版：仙君身份外壳不变，内核切专业法学助教（严谨、条理、术语准确） |
| 消息构建 | 锦囊注入（designMode） | RAG 检索上下文注入（LawSearchService） |
| 流式后处理 | 提炼器（WISH/NO_CARD/炼卡） | **整体旁路**：法学问答不触发 WISH 判定、不炼卡、designMode 不生效 |
| SSE 事件 | chunk/card/done | chunk/**citations**/done（引用 JSON 下发） |
| 持久化 | user/assistant/counsel | user/assistant/**law_citations**（引用存辅助行，与锦囊存法同构） |

### 3.3 上下文控制

法学分支只取最近 20 条消息 + RAG 上下文注入，更早历史截断（防 prompt 膨胀，后续可加摘要）。

## 四、数据库设计

```sql
-- 1. 法条库（知识库，W1）
law_articles(
  id BIGSERIAL PRIMARY KEY,
  law_code VARCHAR(32),          -- CivilCode
  law_name VARCHAR(128),         -- 中华人民共和国民法典
  book VARCHAR(64),              -- 物权编
  chapter VARCHAR(128),          -- 第九章 所有权取得的特别规定
  article_no VARCHAR(32),        -- 第三百一十一条
  article_title VARCHAR(128),     -- 善意取得
  content TEXT,                  -- 条文全文
  tags TEXT[],                   -- 知识点标签
  related TEXT[],                -- 关联条文号
  effective_date DATE,
  embedding VECTOR(1024)          -- pgvector
)

-- 2. 题库（W2）
law_questions(
  id BIGSERIAL PRIMARY KEY,
  source VARCHAR(16),            -- generated | real
  subject VARCHAR(32),           -- 民法/刑法...
  question_type VARCHAR(16),      -- single | subjective
  difficulty SMALLINT,           -- 1易 2中 3难
  knowledge_points TEXT[],
  stem TEXT, options JSONB,      -- 客观题选项
  answer VARCHAR(8),             -- 客观题答案
  analysis TEXT,                 -- 解析
  key_points JSONB               -- 主观题采分点（出题时同步生成）
)

-- 3. 答题记录（W2，画像数据源）
law_answer_records(
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT REFERENCES users(id),
  question_id BIGINT REFERENCES law_questions(id),
  answer TEXT, is_correct BOOLEAN,
  time_spent_sec INT, answered_at TIMESTAMP
)

-- 4. 会话（复用，仅加列）
ALTER TABLE idea_sessions ADD COLUMN mode VARCHAR(16) DEFAULT 'host';
```

**画像不落独立表**：掌握度、遗忘曲线全部从 law_answer_records 实时聚合计算（存答题事实，不存画像快照，杜绝漂移）。

## 五、检索设计（三路融合，替代 ES + Milvus）

```
用户问题
   ├── L1 编号精确路：正则解析「民法典311条 / 刑法第二十条」→ SQL 直查（毫秒级，命中置顶）
   ├── L2 关键词路：pg_trgm 相似度（几千条量级够用）
   └── L3 语义路：embedding-3 实时向量化 → ORDER BY embedding <=> :q LIMIT 20
        ↓
   三路并集，简单加权融合；W4 接 glm-4-flash rerank（top10 相关性打分）
```

- Embedding 客户端：自写 HTTP POST（智谱 /embeddings 端点，OpenAI 兼容），约 30 行
- 入库：一次性 CommandLineRunner（profile 开关触发），1260 条分批调 API（每批 16 条 + 间隔限速 + 失败退避重试）
- 查询缓存：Caffeine 缓存热点问题向量结果（W4）

## 六、引用溯源（防幻觉三道防线）

1. **生成约束**：Prompt 强制「每个论点标注 [n]，n 对应检索上下文编号；仅基于上下文回答」
2. **代码级校验**：生成完成后正则抽取答案中所有 [n]，与真实检索结果集比对；编造引用整段替换为「未找到对应法条，建议核实原文」
3. **低置信兜底**：检索最高相似度低于阈值时，答案前置「仅供参考，请核实法条原文」

前端渲染：SSE `citations` 事件 → 气泡下方「📚 查看法条」折叠区，逐条展示法条全名/条号/原文，可展开。

## 七、四周排期与交付物

| 周 | 任务 | 交付物 |
|---|---|---|
| **W1 地基** | ① PG 换 pgvector 镜像（先 pg_dump 快照）② 民法典开源结构化数据获取清洗 + 导入 Runner + embedding 入库 ③ LawSearchService 三路检索 ④ idea_sessions 加 mode + IdeaChatService 法学分支 + citations 事件 ⑤ 前端「法」tab + 引用渲染 | 民法典问答，带引用可点，仙官一键换挡 |
| **W2 题库** | ⑥ LLM 出题（检索上下文出题保有据 + 同步生成采分点 + 难度分级）+ 真题导入格式 ⑦ 答题交互视图 + 判分 + 解析 + law_answer_records | 能出题能练题 |
| **W3 画像** | ⑧ 掌握度计算（答对 `m+(1-m)α` / 答错 `m×β`，α/β 随难度）+ 遗忘曲线（SM-2 简化）+ 仪表盘（纯 CSS 条形图，不引图表库）+ 周报 LLM 生成 + 薄弱点推荐出题 | 个性化学习闭环 |
| **W4 Agent 化** | ⑨ 意图路由统一入口（glm-4-flash 分类：概念解释/法条辨析/出题/批改/报告/复习推荐/闲聊）+ 法条辨析（双检索对比模板）+ 主观题批改（采分点逐项匹配）⑩ Caffeine 缓存 + 刑法第二科目 + rerank | 完整备考 Agent |

每周构建通过即交付一版，用户自测。

## 八、风险与预案

| 风险 | 预案 |
|---|---|
| PG 换镜像丢现有数据 | 同版本 pgvector 镜像挂原数据卷；升级前 pg_dump 全量快照（本地+服务器） |
| 民法典开源数据质量参差 | 导入后抽 20 条与国家法律法规数据库官网比对 |
| 智谱 embedding 限速 | 分批间隔 + 退避重试（复用 AgentRunner 退避模式） |
| LLM 出题法条依据错误 | 出题必须基于检索上下文（无检索不出题），解析引用过同一套校验 |
| 4.7 调用量翻倍 | 严格分级：flash 承担分类/出题候选，4.7 只做批改/报告终稿 |
| 真题版权 | 仅个人学习声明 + 来源标注，不商用 |
| 法学模式误触发炼卡 | mode=law 分支提炼器整体旁路（代码级保证） |
| 混合历史 prompt 膨胀 | 法学分支截断最近 20 条，更早历史丢弃（后续摘要优化） |
